# Backend engineering role evidence

This maps the skills requested for an Adobe Software Engineer / Member of Technical Staff application to this repository. It is not an assessment against a specific current job posting, evidence of employment at Adobe, or a claim of production operations. File and test references are intended to support an interview walkthrough.

| Requirement | Where demonstrated | Evidence | Remaining gap |
| --- | --- | --- | --- |
| Java | `src/main/java/dev/assetplatform` | Java 21 records for DTOs/events, explicit domain transitions, constructor injection, bounded streams and try-with-resources; Maven enforces Java 21 | No profiling-driven JVM tuning or production traffic history |
| Data Structures & Algorithms | `validation/StreamingPatternMatcher.java`; [algorithm rationale](ALGORITHMS.md) | KMP prefix table and persistent chunk state; deterministic reference comparisons and trailer boundaries; used by PDF inspection | Fixed five-byte workload is small; this does not demonstrate a general distributed scheduler |
| Client/server architecture | Controllers, DTOs, Node smoke/load clients | Authenticated HTTP uploads, 202/Location receipt, polling, paginated reads and SSE replay | No first-party UI or public download path |
| Spring / Spring Boot | `config`, `service`, `worker` | Security filter chain, validated configuration, explicit transaction propagation, scheduled relay, Kafka listener; full context startup in integration tests | API and worker remain one codebase; no process-isolated parser |
| Hibernate / JPA | `domain`, `repository`; Flyway V1/V2 | Entities separated from DTOs; `@Version`; pessimistic aggregate locks; `optimisticVersionRejectsStaleEntityUpdate` and schema constraints | Mixed JDBC/JPA is deliberate but needs care when isolation changes; no large-data query plan study |
| REST APIs | `AssetController`, `AuthController`, `StatusStreamController`; [API](API.md) | Owner-scoped operations, stable idempotent receipt, 409 conflicts, allowlisted pagination/sorting, safe errors, OpenAPI | Offset pagination, no API compatibility test against released clients |
| Docker | Dockerfile, Compose, CI | Multi-stage build, non-root application and Redis configuration, health-gated dependencies, private service DNS, volumes, read-only app root | Compose syntax verified; local engine unavailable, so image build/start and Linux permissions remain unverified locally |
| Distributed systems | `AssetRegistration`, `OutboxRelay`, `ProcessingCoordinator` | Atomic outbox; competing-relay test; acknowledgement/rollback fault injection; duplicate-safe state transitions and durable retry budget | At-least-once delivery, single-broker local configuration, no measured multi-host deployment |
| Automated testing | `src/test`, `benchmarks/load.test.mjs`, `.github/workflows/ci.yml` | Real PostgreSQL and embedded Kafka, shared Testcontainers contract, security/concurrency/failure tests, driver-verdict tests; [current results](VERIFICATION.md) | Live Redis and container contract are skipped locally; no chaos campaign or external penetration test |
| Cloud-ready architecture | `storage/ObjectStorage.java`; [cloud design](CLOUD_ARCHITECTURE.md) | Storage interface, environment configuration, stateless JWT API, durable database/Kafka state, worker/relay role flags | S3 adapter, infrastructure as code, managed-service TLS/IAM, deployment and failover drills are not implemented |
| Secure engineering | [SECURITY.md](../SECURITY.md), [threat model](THREAT_MODEL.md) | Salted PBKDF2, JWT claim validation, ownership, decoded-path rate limits, strict JSON, file bounds, operator-only metrics scope, OSV and secret scanning | HMAC key rotation/revocation, malware scanning, parser isolation, email verification and tenant quotas |
| Agile-quality engineering practices | Git history, CI, dependency automation, review/verification records | One focused hardening commit, reproducible tests, regression cases tied to concrete findings, explicit acceptance gates and limitations | A solo repository cannot prove team ceremonies, collaboration history, code-review participation or incident ownership |

Redis is used for rate counters, not a fabricated caching layer. Authorization is resource ownership plus a separate operator metrics scope; no application-wide RBAC system is claimed. Cloud services are proposed deployment targets, not deployed technologies. Discuss the connection cost of worker coordination and the remaining parser risks rather than presenting the project as production complete.
